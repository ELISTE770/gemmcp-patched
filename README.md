# GemMCP 2.1.2-patched + מדריך התקנה

עותק של [GemMCP](https://github.com/SSSHMUEL) מאת **SSSHMUEL**, מבוסס על גרסה 2.1.2,
עם **שישה תיקוני באגים** והסרה של endpoint אחד מטעמי אבטחה. מאגר פרטי, לשימוש אישי.

GemMCP מחבר את Gemini Web לשרת מקומי קטן שרץ על המחשב, כך שבקשה בעברית פשוטה
הופכת לפעולה אמיתית — פתיחת תוכנה, קריאת קובץ, שאילתת SQL.

```
"פתח מחשבון"
   ↓
Gemini → {"service":"windows","action":"open_app","app_name":"calc"}
   ↓  התוסף תופס ומבקש אישור
   ↓  background.js → localhost:3000
Windows מפעיל את התוכנה
   ↓  התוצאה חוזרת לשיחה
Gemini: "המחשבון נפתח ומוכן לשימוש."
```

בעמוד התוספים של Chrome זה יופיע כ-**`GemMCP for Gemini (patched)` / `2.1.2-patched`**,
כדי שיהיה חד־משמעי שזו לא הגרסה הרשמית.

---

## מה יש כאן

| תיקייה | מה זה |
|---|---|
| `GemMCP/` | הפרויקט המלא, מתוקן. כאן רץ שרת הגשר. |
| `GemMCP-extension/` | קבצי התוסף בלבד (15 קבצים) — **את זו טוענים ל-Chrome** |
| `GUIDE.html` | מדריך ההתקנה המלא, מעוצב. פתח בדפדפן. |

שתי התיקיות מכילות את אותם קבצי תוסף בכוונה. `GemMCP-extension` קיימת כי טעינת
התיקייה המלאה ל-Chrome גוררת גם את `bridge-server/node_modules` — למעלה מ-1,300
קבצים שאינם חלק מהתוסף, וזו הסיבה הנפוצה ביותר לכישלון התקנה.

## התקנה מהירה

**דרישות:** Node.js 18+, Chrome, Windows.

```powershell
# 1. התקנת תלויות השרת
cd GemMCP\bridge-server
npm install

# 2. יצירת קובץ ההגדרות
copy .env.example .env
#    ערוך את WIN_ALLOWED_PATH לנתיב שלך

# 3. הפעלת הגשר
cd ..
.\start-bridge.bat
```

**4. טעינת התוסף:** `chrome://extensions` ← הפעל **מצב מפתח** ← **טען פריט שלא נארז**
← בחר את `GemMCP-extension` (בלחיצה אחת, בלי להיכנס פנימה).

**5. בדיקה:** פתח gemini.google.com, לחץ **Activate GemMCP**, וכתוב `פתח מחשבון`.
אמור לקפוץ כרטיס אישור עם ה-JSON המלא.

בגרסה הזו **אין צורך לכבות ידנית את Auto-Run** — ברירת המחדל היא אישור.

המדריך המפורט, כולל תקלות נפוצות, נמצא ב-`GUIDE.html`.

## התיקונים

כולם אומתו על התקנה חיה. אינם חלק מהמאגר הרשמי — גם לא ב-2.1.2.

### 1. `popup/oauth-success.js` — סוגר יתום

הקובץ היה שבור תחבירית ולא נטען כלל, ולכן דף הסיום של התחברות OAuth לא עבד.
סביב שורה 102 בלוק טיימר נסגר ב-`}` בלי פתיחה תואמת. הוחזרה השורה החסרה `if (!err) {`,
מה שגם משחזר את הכוונה המקורית — הטיימר לא אמור לרוץ בדף שגיאה.

### 2. `bridge-server/server.js` — `open_app` מדווח הצלחה כוזבת ונתקע

הקוד הסיק הצלחה מקוד היציאה של `start`, שמחזירה **תמיד** אפס. שם תוכנה שגוי החזיר
"הופעל בהצלחה" בלי שנפתח כלום, ובמקרים אחרים הבקשה לא חזרה לעולם והשאירה תהליך
`cmd` תלוי לנצח בהמתנה לדיאלוג שגיאה.

התיקון מחליף את ההסקה בבדיקת קיום מראש — `where.exe` לקבצי הרצה,
`reg query HKCR\<scheme>` לפרוטוקולים — ומוסיף timeout של 5 שניות כרשת ביטחון.

| בקשה | לפני | אחרי |
|---|---|---|
| `bogus_app_zzz999` (לא קיים) | נתקע לנצח | 404 תוך 0.4 שנייה |
| `spotify` (לא מותקן) | "הופעל בהצלחה" | 404 תוך 0.02 שנייה |
| `notepad` | עובד | עובד |

### 3. `content.js` — כתיבה לקומפוזר לא מסונכרנת עם Angular

תיבת הקלט של Gemini היא רכיב Angular. ארבעה מסלולים בקוד כתבו ישירות ל-`innerHTML`,
מה שמעדכן רק את ה-DOM הגלוי בעוד המודל הפנימי — זה שנשלח בפועל — נשאר לא מסונכרן.
התוצאה: `Something went wrong (1096)` והתוצאה נתקעת בתיבת הקלט.

כל ארבעת המסלולים עוברים עכשיו דרך `setComposerText()` אחת, שמשתמשת
ב-`document.execCommand('insertText')` — עריכה אמיתית ברמת הדפדפן שמייצרת רצף
`beforeinput`/`input` תקני ש-Angular מאזין לו. השיטה הישנה נשארה כגיבוי.

### 4. `content.js` — זיהוי פקודות נחסם לנצח

`isGeminiGenerating()` החזירה `true` אם קיים בדף **כל** `mat-progress-bar` או
`mat-spinner`, גם מוסתר לחלוטין. מכיוון ש-`scanForToolCalls` נסוגה כל עוד היא
מחזירה `true`, אף פקודה לא זוהתה לעולם.

נוספה `isElementVisible()` שבודקת `display`, `visibility`, `opacity`, `offsetParent`
ותיבה חוסמת, והסריקה כבר לא נסוגה בזמן יצירה. ההגנה מפני JSON חלקי היא בדיקת
יציבות: בלוק צריך להישאר עם טקסט זהה 700ms לפני שפועלים עליו.

אומת מול יצירה אמיתית: כרטיס האישור הופיע תוך 900ms בזמן ש-Gemini שידר בפועל.

### 5. `content.js` — לולאת שליחה אינסופית

ב-`attemptSend`, ה-`return` של "עדיין מייצר" יושב **לפני** בדיקת `attempts >= maxAttempts`,
כך שתקרת 90 הניסיונות לא הייתה ניתנת להשגה בזמן המתנה. נוספה תקרה נפרדת של 15 שניות:

```
[14:18:22] ממתין לסיום התשובה של Gemini כדי לשלוח תוצאה...
[14:18:36] ג'מיני עדיין מסומן כמייצר לאחר 15 שניות – שולח בכל זאת
```

### 6. `content.js` — ה-interceptor בולע את ה-Enter

`attachUserIntentInterceptor` העשיר את תוכן הקומפוזר סינכרונית בתוך הטיפול באירוע
השליחה, ואז נתן לאירוע המקורי להמשיך ל-Gemini — לפני שהמודל של Angular הספיק
להתעדכן. התוצאה: לחיצת Enter לא שלחה כלום, וההנחיה נערמה בכל ניסיון חוזר.

כעת האירוע המקורי נעצר, ההעשרה מתבצעת, והשליחה מופעלת מחדש אחרי 150ms.
`enrichInputIfNeeded` מחזירה בוליאני, כך שאם אין מה להעשיר האירוע לא נוגע בו כלל.
בנוסף הורחב תנאי הסף כדי שההעשרה לא תיערם על עצמה.

### 7. ברירת מחדל בטוחה ל-Auto-Run

`isAutoExecute` היה `true` בשני מקומות, ולכן כל אובדן של המפתח `autoExecute`
מ-`chrome.storage` — למשל הסרה והוספה מחדש של התוסף — החזיר בשקט הרצה ללא אישור.
שונה ל-`false`: המצב הבטוח הוא זה שנופלים אליו.

## מה שהוסר: `POST /api/update`

ב-2.1.2 נוסף endpoint שמריץ `git pull` או מוריד ZIP מ-GitHub ומחליף את הקוד המקומי,
הכל דרך PowerShell — **בלי שום אימות**. מכיוון שה-CORS מאשר גם בקשות ללא `origin`,
כל תהליך מקומי שמגיע ל-`localhost:3000` היה יכול לגרום למחשב להוריד ולהריץ קוד חדש.

ה-endpoint נמחק מהשרת (110 שורות) ו-`triggerBridgeUpdate` ב-`background.js` מחזירה
הודעה מסבירה במקום לפנות אליו. עדכון גרסה נעשה ידנית — שגם מונע דריסה של התיקונים.

> **אם תעדכן ידנית מהמאגר הרשמי:** כל שבעת התיקונים יידרסו. השווה מול המאגר הזה קודם.

## למה 2.1.2 ולא 2.0.1

בדקנו את 2.1.2 מול 2.0.1: **אף אחד מהבאגים לא תוקן שם**. אין תכונות חדשות,
אין שירותים חדשים, אין פעולות חדשות — ב-`manifest.json` וב-`package.json`
השתנה רק מספר הגרסה, וב-`content.js` אין אף פונקציה חדשה.

מה שכן יש: ליטוש נוסח הפרומפט, שיפורי UI, תרגומים, סקריפטי הפעלה טובים יותר
(`find-and-start.ps1` חדש), ו-`/api/update` שהסרנו. לכן לקחנו את 2.1.2 כבסיס
והרכבנו עליה את התיקונים — כך מקבלים גם את הליטוש וגם את התיקונים.

## אבטחה — חובה לקרוא

**הגדרות ה-`.env` אינן מנעול.** הפונקציה `resolvePermissions` ב-`server.js` מאפשרת
ל**גוף הבקשה** לדרוס אותן. בדיקה בפועל: בקשה עם `permissions: {allowedPath: "C:\"}`
קיבלה גישה ל-`C:\Windows\System32` למרות ש-`WIN_ALLOWED_PATH` הוגבל לשולחן העבודה.
אותו דבר תקף ל-`runCommands`.

המשמעות המעשית: כל תהליך מקומי שמגיע ל-`localhost:3000` יכול להריץ PowerShell שרירותי
כל עוד הגשר פעיל. ה-CORS מאשר גם בקשות ללא `origin`.

ההגנה שאמורה הייתה לסגור את זה, `BRIDGE_AUTH_TOKEN`, אינה שמישה — התוסף עצמו לא שולח
את הכותרת `x-bridge-token`, ולכן הפעלתה תשבור אותו.

**שלוש הגנות שכן עובדות:**

1. השאר את **Auto-Run Approval כבוי**. זו ההגנה האפקטיבית היחידה מפני פקודה שגויה.
   בגרסה הזו זו כבר ברירת המחדל.
2. הגבל את `WIN_ALLOWED_PATH` לעץ תיקיות ספציפי, והשאר `WIN_PERM_COMMANDS=false`.
3. הרץ את הגשר רק כשצריך, במקום הפעלה אוטומטית בכל הדלקה.

## תקלות נפוצות

| מה קורה | למה ומה עושים |
|---|---|
| Chrome מסרב לטעון את התוסף | נבחרה התיקייה הלא נכונה. `manifest.json` חייב לשבת ישירות בתיקייה שנבחרה, וצריך לבחור את `GemMCP-extension`. |
| שום דבר לא קורה אחרי בקשה | Gemini לפעמים נתקע במצב "מייצר" אחרי שכבר סיים — אומת בצ'אט נקי, בלי GemMCP. התיקונים 4 ו-5 מטפלים בזה; אם עדיין נתקע, לחץ **Stop response**. |
| תג GemMCP לא מופיע | ה-content script נטען רק בטעינת דף. רענן את הלשונית. |

| הגשר רץ אבל פקודות נכשלות | במחשב מנוהל ארגונית, מדיניות `LocalNetworkAccessAllowedForUrls` יכולה לחסום גישה ל-localhost. בדוק ב-`chrome://policy`. |
| שינית קוד ולא רואה הבדל | העתק את הקובץ גם ל-`GemMCP-extension`, לחץ רענון ב-`chrome://extensions`, ורענן את הלשונית. |
